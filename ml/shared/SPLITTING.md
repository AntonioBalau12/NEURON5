# Shared 70/20/10 split and 10-fold CV

`splits.csv` maps every practice row ID exactly once to `train`, `validation`, or `test` (seed 42), with a group-stratified 70/20/10 outer split. `cv10_folds.csv` maps each outer-train row ID to one of 10 grouped folds; rotate one fold as validation and use the other nine for training. The outer test rows are excluded from CV and should be evaluated once after model selection. The split and folds use greedy assignment of indivisible connected groups. Group edges join normalized duplicate text, identical canonical fact signatures, every shared subject/attribute history, and character-trigram near duplicates with Jaccard similarity at least 0.90. This prevents repeated claims and known temporal histories from crossing partitions. Gold forms are used only for grouping and audit, never as inference features.

Gold forms are used only for grouping and audit, never as inference features. The assignment balances TRUE/FALSE/UNSURE counts and total row counts against the target ratios. A large connected history can make exact ratios impossible; actual counts and date ranges are recorded in `splitting_audit.json`. Date ranges are audited rather than used to force chronological partitions, because chronological and shared-history constraints can conflict. Any temporal generalization claim must therefore be reported separately. Training-only evidence is not used in the split.

Reproduce with `python ml/shared/create_splits.py`. The manifest has columns `id,split`; the fold file has columns `id,fold`.
